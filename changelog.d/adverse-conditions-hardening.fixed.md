- **The sweeper no longer reclaims across an interval it did not observe.** Every reclaim decision is a wall-clock delta against a stored timestamp — "this worker last heartbeat 400s ago, so it is dead" — which is only a valid inference if the broker was _watching_ those 400s. It had two ways not to be: it had just started (the first sweep runs immediately at boot, before any worker can re-heartbeat), or it had been frozen by a host suspend or a stalled loop. Either way the first post-gap sweep saw the whole fleet as dead and every in-flight job as reclaimable, and acted on all of it at once — including the `wall_clock_exceeded` branch, whose terminal `resurrect` does **not** undo, so healthy long-running jobs died permanently and cascade-cancelled their dependents. `sweep_once` now records each pass and suppresses the time-based terminal phases (scheduling-timeout expiry, ASSIGNED reclaim, RUNNING wall-clock backstop and dead-worker reclaim/orphan) for one cycle when process uptime is under the reclaim window or the gap since the previous pass far exceeds the sweep interval. Worker offline/stale marking, retention, env scrub, version drift and the queue warnings keep running — none of them ends a job, and all self-correct on the next heartbeat. Suppression is logged and emits a `reclaim_suppressed` event, so a sweep that declines to reclaim is never mistaken for one that found nothing to reclaim.
- **A full disk no longer turns every job-log chunk into a 500.** `POST /jobs/{id}/log` wrote the chunk with no guard, so `ENOSPC` propagated: the worker swallowed the error and kept going — the job survived but its output vanished silently — while the broker wrote a stack trace per chunk to the same full disk. The write is now guarded and reports the drop in the response body (`{"bytes": 0, "dropped": N, "reason": ...}`) rather than raising, matching the principle `_emit_event` already applied one module over: observability must never break broker liveness.
