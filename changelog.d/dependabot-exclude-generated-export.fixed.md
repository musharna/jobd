- **Dependabot no longer opens PRs against the generated Docker requirements export.** `docker/requirements-docker.txt` is a `uv export` of `uv.lock`, not a manifest, but Dependabot's pip ecosystem kept discovering it and opening PRs that edited it directly — desyncing the export from its own source while leaving `uv.lock`, which CI installs from, untouched. Such a PR is red by construction (the lockstep lint compares the committed file against a live export of the PR's own `uv.lock`, so a rebase cannot fix it), and merging one would ship dependency versions no test has ever run into an image whose `--require-hashes` install exists to prevent exactly that. It is now excluded via `exclude-paths`. The previous mitigation — relocating the file under `docker/` — rested on the belief that a pip entry at `directory: "/"` scans only the root; that belief was wrong, and its deploy-lint could not detect the fact because it asserted the workaround was _in place_ rather than that it _worked_. The lint now pins the exclusion itself, with its own matcher tests.
