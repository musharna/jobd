- **A worker the broker refuses now says so, instead of polling forever in silence.** The poll loop treated every non-200 from `/next-job` as "no job", so a worker whose payload the broker rejects — most plausibly a `422` because the worker predates a field the broker now requires — backed off and re-polled indefinitely while logging nothing. It now warns on the first refusal and at most once a minute thereafter, with the suppressed count and the broker's response, naming the likely cause. That matters because mixed versions are a designed state: installs pin a worker to the broker's version, `update-worker.sh` defers upgrades while a worker is busy, and `version_drift` exists because prolonged mismatch is expected.
- **The worker↔broker request contract now has a compatibility floor in CI.** `NextJobQuery` and `WorkerHeartbeat` declare required fields with no defaults, so adding one silently locks out every older worker — and nothing caught it. `tests/test_worker_payload_compat.py` freezes the minimum payload an older worker sends and asserts it still registers, still claims, and still receives a real job; a companion test proves every key in that payload is load-bearing, so the floor cannot rot into a bloated dict that passes vacuously. Adding a required field now fails CI with an explanation instead of stranding the fleet.
