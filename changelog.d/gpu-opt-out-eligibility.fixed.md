- **Queue explanations now match dispatch on the GPU opt-out.** v0.5.56 kept VRAM requests and `any-gpu` pins off a `gpu: false` worker at dispatch. The views that explain a queue still counted that worker as eligible, because `eligible_workers` and `submit_preflight` never saw the job's VRAM. So a VRAM job pinned to an opted-out host was reported as "will queue behind job N" and then as "the only eligible worker is busy", although it could never run there. One shared predicate now drives dispatch, `eligible_workers`, `selectors_only_match` and `submit_preflight`. Submit says plainly that every matching worker has GPU work switched off, and `vram_gb` is now a required argument, so no caller can skip the check.
