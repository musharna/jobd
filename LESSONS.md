# Lessons

One line per miss: the class, and the mechanism that now catches it.

- 2026-11-14 — A plain `pip install jobd` installed `jobd-worker` and `jobd-mcp`, whose modules import packages only the `worker` and `mcp` extras bring, so on a base install both commands died with a `ModuleNotFoundError` traceback. Every check that ran them had installed the extra first: CI syncs all three extras, and the quickstart dry-run installs `jobd[worker]` and `jobd[mcp]` before it starts either one. Found by the wheel install check on the day it was adopted. Now: `scripts/wheel_smoke.py` loads every console script on a base install in `guardrails.yml`, and `tests/test_entry_points.py` holds the two commands to `jobd._entry`, which names the extra.
- 2026-11-14 — Two tests changed state that outlives a test and that `monkeypatch` cannot put back, and one pass of the suite could not show it: the subreaper tests made the pytest process a child subreaper with a real `prctl` (they run last), and the MCP stdio test relied on a `sys.stderr` default the client library binds at first import. A second pass in the same process, which is how mutmut takes its baseline, failed nine watchdog tests by five seconds each and the MCP test outright. Found by the first mutation baseline. Now: an autouse fixture restores the subreaper bit after every test (`tests/process_state.py`), the MCP test passes `errlog` itself, and the nightly mutation job runs the suite twice in one process every night.
- 2026-11-14 — The privacy-scan skip for the template workflows was tested under an environment I assumed (`GITHUB_ACTIONS` and `GITHUB_WORKFLOW` set), and the real "tests with no network" step runs through `sudo`, which drops both: the adoption PR's first CI run skipped in the plain step and failed both scans in the no-network one. A test of a CI step's environment that sets the variables by hand encodes the belief it should be checking. Now: `scripts/guardrails-setup.sh` leaves the workflow's name in a file under `HOME`, which that step keeps, and the test builds its environment from the `KEEP=` list in `guardrails.yml` itself.
